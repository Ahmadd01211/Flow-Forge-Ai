# Project status

Date: 23 October 2026 (Asia/Karachi).

Phase 4 now includes guided simple input/output schema editing, advanced JSON preservation, expandable tool contracts/permissions, corrected tool-grant summaries, viewer read-only controls, and a publication checklist sharing the backend's actual publish rules. A versioned output-token ceiling (16–4096) is enforced in standalone and workflow agent runs. Historical stored versions without this field retain their JSON/hash and use the prior default ceiling. See [agent-builder walkthrough](learning/11-AGENT-BUILDER.md). This phase adds no migration or paid provider call.

Phase 3 now exposes one backend-owned execution capability and pricing profile per listed model, consumed by Integrations, Agent Builder and version history. Eleven reviewed IDs include the four new profiles GPT-5 Nano, GPT-5, Gemini 2.5 Flash-Lite and Claude Sonnet 4.6. All three reviewed OpenAI profiles can use the bounded local-tool loop. Admins can refresh a model catalog using the saved encrypted key without rotating it or invalidating credential generations. Refresh failure preserves saved state; model removal blocks new runs and clears an unavailable default. Fixed-host catalog pagination has bounded pages/bytes/time. Other listed models are clearly marked setup only. See [provider capabilities](learning/10-PROVIDER-CAPABILITIES.md) for exact scope, official sources and limitations. No live paid provider calls were used for this phase.

Phase 2 (accounts and workspaces) now includes email verification, password recovery/change, sign-out on all devices, workspace creation/rename, emailed invitations, member role changes/removal, and ownership transfer with last-owner protection. Invitations require verified sender/recipient identities and cannot outlive the inviter's permission to grant access. Email links are single-use, hashed in token tables, and expire; email bodies are encrypted in a transactional outbox with bounded delivery retries. Development SMTP is captured in Mailpit at http://localhost:8025; public email requires operator SMTP configuration. Existing accounts can request verification from Settings. See [phase plan](DEVELOPMENT_PHASES.md) and [accounts walkthrough](learning/09-ACCOUNTS-AND-WORKSPACES.md).

Webhook and schedule node types currently only pass through explicitly supplied run input. They do not register inbound webhooks or automatic schedules. Phase 8 remains incomplete.

FlowForge AI has a working Next.js and FastAPI foundation, immutable agent test snapshots, version history, comparison and restore, and an offline JSON contract playground. Workspace owners/admins can verify, encrypt, rotate and revoke separate OpenAI, OpenRouter, Claude, Gemini and DeepSeek API keys. An editor can choose a provider and listed model, then publish an immutable agent definition after saved-revision and schema checks. Published OpenAI GPT-5 Mini, Gemini 2.5 Flash, DeepSeek Flash/V4 Pro, Claude Haiku 4.5, and OpenRouter GPT-4o-mini versions can now execute as live runs; contract validation and publication alone do not call a model.

The backend stores snapshots and audit events in PostgreSQL with transactionally assigned version numbers, workspace ownership, unique constraints, and database triggers that reject changes or deletion. The application database role has only read and insert access to these records. Snapshot creation checks the saved draft revision and returns the existing snapshot for repeated requests at the same revision. Contract validation has bounded payload and schema complexity and returns field paths without echoing submitted values.

The backend encrypts provider credentials with AES-256-GCM under a separate local key mounted read-only into backend containers. Stored ciphertext is bound to workspace, connection and generation. Published versions pin the connection and generation so a later runner can reject old publications after rotation or revoke. The Integrations screen now uses one setup flow with a provider selector, key verification, searchable available-model list, and a saved default model per provider. New agent drafts start with a saved default; existing drafts retain their own choice. Agent and integration API types are generated from FastAPI OpenAPI, with drift checks in CI. The workflow canvas, draft APIs, authentication, CSRF protection, workspace authorization and Redis rate limiting remain in place.

The first execution slice stores encrypted inputs and outputs in PostgreSQL. Redis/Celery deliver run IDs, while PostgreSQL owns the state. A maintenance process redelivers queued runs, recovers pre-call worker crashes, and expires overdue work. Ambiguous outcomes after a provider call may have begun are not automatically retried. The Runs screen shows state, validated output, token use, measured or uncertain cost, and cancellation. A per-run reservation and output-token cap limit expected spend, but the estimate is not a billing guarantee or a workspace-wide quota.

The Tool Registry now offers two reviewed, bounded read-only handlers: JSON value extraction and literal text replacement. Workspace owners/admins approve or remove them, and editors can test approved tools. Agent drafts can select approved tools; publication freezes their grants. OpenAI GPT-5 Mini runs can now call those tools through a bounded, stateless function-call loop. Workspace approval is checked at submission and immediately before each call. The [agent harness guide](learning/05-AGENT-HARNESS.md) explains the control flow and limits. A new append-only event table records run, model and tool step metadata; the Runs screen displays the trace without exposing input or arguments.

Integrations includes an MCP connection path using the official Python SDK. Platform operators curate HTTPS server URLs and explicit tool-name allowlists through `MCP_CATALOG_JSON`; they can mark a reviewed subset `read_only_tools` for workflow execution. Workspace admins connect or rotate an encrypted bearer token and editors can test the approved tools. The connection stores bounded tool descriptions and input schemas, cleared on revoke. A published MCP workflow node pins the connection generation and schema hash, validates arguments, checks current approval, and marks the run before the remote call so a worker crash cannot silently replay it. Tenant-submitted URLs and unreviewed remote tools are not accepted. The local preview starts with an empty MCP catalog; connecting a real server requires an operator-reviewed endpoint and credentials. MCP calls from inside an agent's model tool loop remain unimplemented.

The Templates page has five reviewed starters. The new-agent editor offers three editable quick starts with matching instructions and schemas. The workflow builder now has ten functional node types: input, agent, approved local tool, approved read-only MCP tool, condition, transform, text template, list filter, JSON parse and result. Draft preview runs local nodes. Published workflows can route one condition into true and false paths that rejoin at result; the trace records the chosen path. Text templates interpolate JSON Pointers, list filters select up to 200 items, and JSON parse converts bounded text to structured data. Published runs support at most one agent and reviewed tools. The agent node accepts tool-using OpenAI GPT-5 Mini versions, with local grants checked at submission and before each call; the smaller agent/workflow budget applies across its loop. The agent step pins an immutable version, checks the credential and input schema, and records model usage. Maintenance never replays a run after an external-call marker. See [agent workflow steps](learning/08-WORKFLOW-AGENT-STEPS.md).

Hosted deployments now give workspace owners/admins a version-pinned endpoint for a published agent or linear workflow. The bearer key appears once and is stored only as a hash. External clients submit idempotent input and poll their own deployment's runs. Rotation invalidates the old key; revocation blocks access and requests cancellation of active runs. Redis limits submissions and status reads per deployment. The local Compose edge binds to localhost.
