# MCP, templates, and workflow preview

The MCP connector lets a platform operator review an external Streamable HTTP server before any workspace can reach it. The operator supplies `MCP_CATALOG_JSON`, an array of server IDs, display names, public HTTPS URLs, exact allowed tool names, and an optional `read_only_tools` subset. The workspace API accepts a server ID, never a URL. A workspace owner/admin may provide an optional bearer token; FlowForge verifies the remote tool list, stores only the allowlisted intersection, and encrypts the token with the same AES-GCM key used for provider credentials. A workspace editor may test a verified tool with bounded JSON arguments. Revoking the connection deletes the encrypted token from the active row and blocks tests and new workflow runs. Only operator-reviewed `read_only_tools` appear in the workflow MCP node picker. Publishing freezes the connection generation and input schema hash; credential rotation or schema change requires a new workflow version. Arguments are validated against the frozen schema before a call. MCP nodes execute in durable runs, not draft preview.

Remote tool descriptions and annotations are untrusted data. The operator allowlist is the permission source. URL parsing, public DNS checks, same-origin redirect behavior in the SDK, disabled environment proxies, request timeouts and output-size limits narrow the network surface. Production deployment also requires an outbound firewall or proxy that blocks private and metadata IP ranges, because a DNS check before connection alone cannot eliminate rebinding.

Templates are code-reviewed definitions, not a marketplace. Instantiation copies a definition into a normal private workspace draft. The agent templates still require the user to select a connected provider and model before publication. Workflow templates can be edited in the visual canvas. The Text cleanup template can be previewed after `text.replace` is approved in the Tool Registry.

Workflow preview deliberately has a smaller contract than durable execution: local deterministic nodes and reviewed local tools only, five seconds, and 64 KiB per input/output. It validates the saved revision, input/output schemas, tool approvals and mappings. The response shows step outputs, but it is not stored as an execution record. Provider and MCP calls require a published durable run.
