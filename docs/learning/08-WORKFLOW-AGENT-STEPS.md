# A published agent inside a workflow

The executable agent node supports one published agent per workflow. In the builder, insert **AI agent**, choose a published version in the inspector, then save, validate, publish and run. Draft preview runs local nodes; it deliberately does not call a provider, so an agent step needs a durable run. Published OpenAI GPT-5 Mini agents may call approved local tools through the bounded tool loop.

The graph stores the immutable agent version ID. Validation checks that the version belongs to the workspace, has a supported live adapter, has no tool grants, and still has an active matching credential generation. Submission and the worker repeat those checks. The worker validates mapped input against the agent input schema, calculates an output-token allowance from the smaller of the workflow and agent budgets, decrypts the provider key only inside the worker, and validates the model output against the published schema. The workflow result and step output are encrypted at rest.

The worker commits `external_started_at` before the model request. After that point, maintenance never requeues the run automatically: a worker crash could otherwise charge the customer twice. A stale run eventually fails at its deadline with a possible-charge estimate. Successful responses record provider-reported tokens and estimated cost, including when a later step fails.

The builder lists published versions suitable for this runtime, including versions with approved local tool grants. A version disappears from the picker after credential rotation or tool revocation; previously published workflows reject new runs until grants are restored or a new version is chosen. Approval is checked again before each tool call. The smaller agent/workflow budget applies to the whole tool loop. A transform node constructs up to 32 output fields from literals or pointers into incoming data, with an optional object output schema. A condition compares two values and selects one of two paths; both must converge at the result node. Text template, list filter and JSON parse handle common deterministic data preparation. Multiple agent nodes and more complex branching remain future slices.

Tests use fake provider responses. To test manually, connect your own provider key, publish an agent, create a workflow with Manual input → AI agent → Return result, and submit JSON matching the agent input schema. For tool use, approve a local tool in Tool Registry and select it in an OpenAI GPT-5 Mini agent before publishing.
