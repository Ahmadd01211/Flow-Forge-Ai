## Delivery order

Delivered: API actions/credentials, visual field mapping, execution debugging, portable action templates, bounded iteration/subworkflows and local restore verification. Also delivered: durable approvals/timers with activity export, guided GitHub/Slack recipes and cron schedules, plus approval pauses for write-capable MCP calls inside the agent tool loop, conversation memory, eleven starter skills with immutable publication, guided recipe discovery and skill handoff, and provider readiness guidance. Next agent work: a pgvector knowledge base and further harness expansion. Next orchestration work: richer expressions (JMESPath), then bounded Repeat-until loops built on them. Next trigger work: signed GitHub/Slack webhook receivers. Add OAuth only when its lifecycle can be tested with real accounts. Implement each as a tested vertical slice with permission, failure and credential-revocation handling. Tenant-controlled workspace quotas now exist; add operator-owned plan ceilings before public multi-tenant hosting. See [loops and reusable workflows](learning/19-WORKFLOW-LOOPS-AND-SUBWORKFLOWS.md) for this completed phase and its verified limits.

## Guided creation acceptance

The built-in inventory is 13 recipes, 11 starter skills and 20 workflow node types, verified from the template/skill catalogs and workflow schema. Created resources are workspace-visible drafts. Copied skills must be reviewed and published before agent tests; publication freezes versions. Local workflow preview and publication-required durable runs remain separate actions. The [noncoder GUI checklist](manual-testing/noncoder-creation.md) covers these paths and provider verification with the user's own key. Final GUI walkthrough and live-provider generation acceptance remain outstanding for the user.

## Scope and evidence

Published versions, credential checks, hosted bearer keys, local tools and MCP agents/workflows under per-tool policies exist. Trigger nodes now have separate durable automation bindings. Tests must use an isolated PostgreSQL database ending in `_test`; local compile checks alone do not verify runtime behavior. Real provider/MCP/OAuth testing requires the corresponding configured service; no secrets should appear in test output.

Production work involving DNS, external accounts, billing providers and security review remains separate from locally verifiable code. Update PROJECT_STATUS.md with the actual checks and limitations after each delivered slice.
