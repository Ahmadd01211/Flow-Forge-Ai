## Delivery order

Delivered: API actions/credentials, visual field mapping, execution debugging, portable action templates, bounded iteration/subworkflows and local restore verification. Also delivered: durable approvals/timers with activity export, guided GitHub/Slack recipes and cron schedules. Next agent work: approval pauses inside the agent tool loop, conversation memory, then a pgvector knowledge base. Next orchestration work: richer expressions (JMESPath), then bounded Repeat-until loops built on them. Next trigger work: signed GitHub/Slack webhook receivers. Add OAuth only when its lifecycle can be tested with real accounts. Implement each as a tested vertical slice with permission, failure and credential-revocation handling. Tenant-controlled workspace quotas now exist; add operator-owned plan ceilings before public multi-tenant hosting. See [loops and reusable workflows](learning/19-WORKFLOW-LOOPS-AND-SUBWORKFLOWS.md) for this completed phase and its verified limits.

## Scope and evidence

Published versions, credential checks, hosted bearer keys, local tools and MCP agents/workflows under per-tool policies exist. Trigger nodes now have separate durable automation bindings. Tests must use an isolated PostgreSQL database ending in `_test`; local compile checks alone do not verify runtime behavior. Real provider/MCP/OAuth testing requires the corresponding configured service; no secrets should appear in test output.

Production work involving DNS, external accounts, billing providers and security review remains separate from locally verifiable code. Update PROJECT_STATUS.md with the actual checks and limitations after each delivered slice.
